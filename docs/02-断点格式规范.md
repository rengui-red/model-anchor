\# 断点格式规范



`anchor.md` 定义字段约定本身；本文件定义断点层特有的\*\*判定逻辑与写入细则\*\*，两者不重复。



\## 字段与写入规则（引用 anchor.md，此处只列断点层特有部分）



| 字段名 | 含义 | 断点层特有规则 |

|---|---|---|

| `当前` | 正在做什么 | 必须是\*\*可执行动作\*\*，不是状态描述。反例：“在做认证模块”；正例：“把 login 接口的 token 校验从 header 移到 cookie” |

| `下一步` | 接下来做什么 | 必须\*\*单一任务\*\*，不列多个候选。多个候选说明还没想清楚，应先决策再写断点 |

| `阻塞` | 卡住的事 | 没有写“无”；无法确认是否解除，保留原值并标注 `待用户确认`，不擅自清空 |

| `交接备注` | 换模型时需特别交代的事 | 可选。写“新模型容易犯的错”，不写项目背景（背景属于 CLAUDE.md） |



\## 过期判定



\- 判定依据：`断点.md` 的文件修改时间（mtime）

\- 默认阈值：24 小时

\- 行为：`pack.py` 在打包前打印提醒到 stderr，\*\*不阻断打包\*\*，退出码仍为 0

\- 可通过 `--no-stale-check` 跳过



\## 写入责任归属



| 场景 | 谁写 | 机制 |

|---|---|---|

| 会话正常结束 | AI | `hooks/stop-update.md`（v0.2） |

| 用户主动刷新 | AI | `/anchor-update` 命令提示词（v0.2） |

| 钩子未配置 | 用户 | 手动编辑，或调用任意 AI 按模板更新 |

| 过期未更新 | 工具提醒 | `pack.py` 的 stale check |



\## 增量更新原则



AI 更新断点时，先读当前断点内容，再读会话摘要与 git 最近提交，做\*\*增量更新\*\*而非覆盖。只从 `feat`/`fix` 提交推断完成项；`chore`/`docs` 提交不算进展。
