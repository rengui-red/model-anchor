\# 打包器设计



\## 三种模式



| 模式 | 命令 | 输入 | 输出规模 | 适用场景 |

|---|---|---|---|---|

| minimal | `--minimal` | 断点四字段 | 约 500-1500 token | 额度紧张、简单接续 |

| full | 默认（v0.2） | 断点 + 项目 CLAUDE.md/AGENTS.md | 约 2000-4000 token | 复杂项目交接 |

| task-scoped | `--task "关键词"`（v0.2） | 断点 + 与关键词匹配的行 | 介于两者之间 | 聚焦单一任务 |



v0.1 只实现 minimal；full 与 task-scoped 保留函数签名，`pass` 实现。

这是全项目唯一需要遵守的依赖倒置点：所有模式都调用 load_anchor()，不直接读文件。未来切换为 HTTP 请求或 SQLite 查询，只改此函数体。这是“已定义、未激活”的扩展接缝，不是提前实现。

model profile 机制（v0.2）

profiles/<model>.md 是纯字符串模板，不是适配器：

claude.md：结构化标题、长上下文友好

deepseek.md：简洁平铺、直接

doubao.md：中文指令、少术语

generic.md：默认措辞

profile 只影响 prompt 的措辞与结构，不影响档案内容。新增模型 = 新增一个 profile 文件，不改代码。这是“模桥通配”在打包层的体现。

输出约定
打包结果输出到 stdout，提醒信息输出到 stderr

退出码：0 成功（含过期提醒），1 断点文件缺失，2 参数错误

不写临时文件，不修改断点文件本身
